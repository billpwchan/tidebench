# 专业量化平台：领域设计与交付记录

日期：2026-10-08。基线：v0.3.1。本文记录实现决策及验收进展；目标能力只有通过对应工作流后才标为完成。

## 产品范围与成功条件

服务独立系统化交易员和小型研究／自营团队，覆盖 OKX 现货及 USDT 线性永续的历史研究和持续本地模拟。专业能力以完整经济工作流判断：假设与版本 → 合格输入 → 含成本研究 → 证据审查 → 受控模拟发布 → 可解释决策 → 组合绩效／异常处置 → 修订或回滚。

不同策略的输入精度和执行要求应明确。当前授权不包含真实交易所下单；盘口／HFT 不能从 OHLCV 获得可信结论，也不会以新增名称冒充实现。

## 调研与取舍

- [LEAN Algorithm Framework](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview) 分离选币、信号、组合目标、风险和执行，也指出默认组合模型不适合所有紧密耦合的进出场策略。采用职责边界，同时保留事件式交易表达。
- [NautilusTrader architecture](https://nautilustrader.io/docs/latest/concepts/architecture/) 展示共用核心、时钟、状态与端口适配的边界。历史与前向共用经济规则和决策代码，环境提供时间和可见市场事件。此处是设计借鉴，不是成熟度等价声明。
- [Freqtrade strategy customization](https://www.freqtrade.io/en/stable/strategy-customization/) 将入场、退出、标签、持仓管理和数据准备视为策略契约的一部分。Tidebench 不能把指标方向函数当作完整策略。
- [Backtest overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) 说明多次试验会带来选择偏差。试验登记、预声明目标和保留集使用记录需覆盖多个 run，而非仅检查单次 train/test 的代码。

继续采用模块化单体，保留现有可重放输入、Decimal 合约原语、事务账本与恢复。先建立正确领域契约；是否换用成熟引擎，以相同事件的差分验收、维护成本与模型适配决定，不以增加依赖或微服务数量证明专业性。

## 领域契约

1. **策略版本。** 策略项目下保存不可改写的定义、经济假设、参数、时间周期、产品能力、方向／杠杆、退出和定仓政策、实现身份与内容哈希；修改创建新版本。研究记录精确绑定版本。
2. **研究与试验。** 保存假设、预声明目标／约束、基准、版本化输入、候选与失败记录。保留集有明确窗口与访问关系；不同运行不能默默重置尝试计数。
3. **发布修订。** 从指定研究候选生成部署预览，捕获研究结果哈希、选中配置、版本、成本模型、风险政策和库存条件。用户审查具体差异后发布；服务器按预览哈希再次验证，不重新猜测或输入参数。政策变化必须可见并阻断失去批准依据的新风险。
4. **策略运行。** 决策保留所见数据范围／版本、特征、状态前后、目标、否决理由与订单关系。指标可分块更新并恢复；不同环境的时间由显式时钟提供。
5. **组合。** 多市场同步事件、统一资本和风险预算、确定的退出优先／再平衡顺序、最小数量与缺失数据政策。两腿交易必须表达非原子成交与对冲失败。经济净仓和策略贡献分别核对。
6. **绩效。** 记录真实模拟权益时间序列、资金流、收益、费用、资金费和策略归因。完整性不足时不给伪精确指标；静态压力不冒充概率风险估计。
7. **数据与资源。** 前向增量序列与不可变研究快照分开；输入内容寻址、候选共享输入、明细分页／压缩。数据可得时间和历史市场集合由证据声明，缺少时不自动当作已知。
8. **运行治理。** 进度心跳／截止、新鲜度、错误分类、可处置告警、持久暂停、恢复与升级。Example 提供可控时钟和故障演练，而非固定一刻的数字。

## 交付顺序与状态

| 工作包 | 验收 | 状态 |
|---|---|---|
| 策略注册与研究发布 | 不可变版本、研究绑定、明确候选、审批与事务部署；并发／漂移拒绝 | 单市场闭环已验收；组合版本发布继续推进 |
| 策略表达与状态 | 五类规则、有界程序、退出／定仓、分块与重启一致、失败假设 | 已验收指定模型；非任意代码／盘口策略 |
| 多资产与两腿模型 | 2–10 同步市场、共享资本、减仓优先、现金缩放、顺序成交与残差、独立切分 | 历史研究已验收；托管多腿前向继续推进 |
| 研究治理 | 试验登记、固定成本／基准／否决计划、一次性保留集、别名／warmup 防绕过 | 单策略已验收；组合治理继续推进 |
| 前向数据／绩效／时钟 | 增量检查点、可控时钟、真实净值／资金流、决策订单 | 账户观测已验收；策略贡献归因继续推进 |
| 资源与运维 | 进程隔离／截止／父进程死亡、压缩／预算／进度、异常处置、恢复 | 短时负载和故障已验收；持续运行证据继续采集 |
| 交易员界面 | 策略→研究→审查→部署→退出，组合／保留集、桌面／移动／中文 | 12 条 Chromium 工作流；真实用户及更多设备独立验收 |

[当前自审](audit/red-team-0.4.0.zh-CN.md)与[验收记录](verification.md)保存证据。过去验收不能自动覆盖新增能力。真实持续运行时间、外部主机及用户体验研究需要据实记录；不能用加速时钟伪造服务可靠性。

运行隔离参考 [Python futures](https://docs.python.org/3/library/concurrent.futures.html)、[Linux parent-death](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)；监控参考 [Google SRE](https://sre.google/sre-book/monitoring-distributed-systems/)。
