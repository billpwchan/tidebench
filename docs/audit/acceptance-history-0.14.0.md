# v0.14 acceptance history

Two agents without inherited conversation history independently reviewed the v0.13 trader paths and visual hierarchy. Their original reports retain fixed source links to `2b66f9c`; they are internal assessments, not institutional certification. The [implementation review](trader-experience-0.14.0.zh-CN.md) records each baseline finding as completed, partial or pending. ## Material intermediate observations

- Source review confirmed that inspecting a market replaced the execution page and could discard an order draft; submitted fills and canceled instructions could disappear from the Working filter without an exact result. An app-owned read-only inspector and explicit source/ID receipts now retain the current task. Rejection, response uncertainty and actual server quantities have distinct rendering.
- The first focused browser run collected 30 paths: 23 passed, 5 failed and 2 skipped. It exposed a real compact-layout defect: parts of the first position were below the 664px viewport. A separate account-expansion row and redundant unit text consumed the space. The expansion control is now inside the metric strip, the notices are shorter, and the complete position with its details/reduce actions is checked at 390×664. Other failures were ambiguous inspector selectors and a detail toggle test closing its own expanded row; those selectors and test state were corrected.
- The next focused pass completed 28 paths with 2 desktop-only skips. An initial whole-suite pass completed 236 paths with 2 skips. Neither is presented as final-source acceptance.
- Independent screenshot review found a centered market name above a left-aligned product/side label and small market/menu/search targets. The entire market identity is now one left-aligned button; the main mobile targets are at least 44px. Desktop review checks both 1440px and 1200px, including perpetual liquidation and P&L with the ticket open.
- A subsequent source audit found late manual-deployment and strategy-stop responses could cross a changed authenticated session. Both request contexts now include session/source ownership. Missing reported fill quantity also used to fall back to zero; it now remains unavailable. Retry removing its focused button could leave keyboard focus outside the inspector; Tab and Shift+Tab now recover within the dialog.
- The first expanded guard run had four failures caused by expecting the old accessible label `Cancel` instead of the actual `Cancel order`; this was a test-entry mismatch, not a canceled-order acceptance result. The exact visible labels were corrected without force clicks or increased timeouts.
- The same audit found that a canceled Working row could disappear while the HTTP response was lost. Both account views now keep an explicit unconfirmed receipt with the known target source/market/ID and a precise inspection link. Two regression paths remove the row and return 503; they must show uncertainty rather than fabricated canceled quantities.
- Exact order inspection still reads all pending plus the latest 200 terminal orders, 100 audit events and 500 ledger rows. It does not provide an unlimited order-history endpoint. Those bounds are disclosed in the interface and task documentation. The absence of evidence outside a window is not treated as proof that an order never existed.
