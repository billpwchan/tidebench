# 从用户要完成的工作组织 Tidebench

## 本次判断

账户总览、策略库和研究表单的美观程度，不能回答用户能否连续完成交易研究。v0.17 的实际页面巡查与路径回归发现三个断点：组合假设需要用户自行寻找对应配方；研究入口先强调技术输入而不是经济问题；历史研究审查可能挤占正在运行的策略监控。进一步执行刷新验收，发现配方缺少生命周期空数组，导致本地草稿恢复校验失败。本次修复以这些可复现的问题为范围。

评估单位是“用户从什么状态开始，带着什么对象，要做什么决定”，而不是页面数量。交易员也不必遵循单一向导：已经知道输入的人可直接准备数据，日常监控不应先经过策略库。

## 两种使用节奏

| 起点和目标 | 路径 | 必须保留的上下文 | 完成标准 |
| --- | --- | --- | --- |
| 有新交易想法，判断是否值得研究 | 总览 → 假设库 → 策略版本或对应组合草稿 | 经济机制、淘汰条件、市场与配方 | 不靠记忆切页重建配置；创建草稿不提交研究或下单 |
| 已确定市场与时间窗，先准备输入 | 总览 → 数据包 → 当前研究 | 来源、UTC 窗口、已有假设、编辑的成本和资金控制 | 数据准备返回原工作；刷新后仍可继续 |
| 在已有草稿上尝试另一种组合想法 | 假设库 → 保留／替换选择 → 组合研究 | 旧草稿与新提议分别可辨认 | 保留不改旧工作；明确替换重置草稿，不改服务器证据 |
| 查看刚完成的研究并作决策 | 总览的具名记录 → 指定研究结果 → 分析／下一次草稿／研究账本 | 来源、不可变研究 ID、已保存版本、结果与当前草稿的区别 | 回到准确对象；失败或证据不足也可结束或继续研究，不被引导直接激活 |
| 日常管理运行中的模拟策略 | 账户 → 异常／控制器 → 指定部署或组合 | 持仓、来源、控制器身份、当前状态 | 异常优先，其次运行监控，再到研究；历史记录不压住当前责任 |
| 停止策略并处理剩余库存 | 指定控制器 → 停止回执 → 账户持仓 → 独立减仓决定 | 已成交库存、整个组合范围、停止与平仓的区别 | 不将停止控制器误表示为库存已经归零 |

后面三条的结果分析、发布审查、精确控制器回执和停止流程已有实现；本次新增的是入口、排序和上下文可识别性，而不是改写这些经济操作。

## 实施约束

- 空白研究的主入口先明确假设，同时保留直接准备数据的入口。
- 资金费率、截面轮动、风险预算轮动从各自假设直接进入匹配的组合草稿。单策略继续使用原策略版本链路。
- 已有组合草稿不自动覆盖。替换提示明确资金、成本、数据选择会重置；保留和替换均只操作当前浏览器草稿。
- 配方腿使用完整草稿默认结构；保留严格恢复校验，修复缺字段的生成路径。
- 配方选择早于数据目录返回时，先显示正在匹配；目录返回后只补齐仍符合原提议的组合腿。成本编辑保留，组合腿已经编辑则不自动绑定。提交路径验收检查实际准备的 4H 包 ID，避免借用其他时段的数据误通过。配方说明显示其真实周期。
- 已绑定版本的研究草稿展示保存的经济假设；历史结果保持独立，不因展示草稿而更换选中结果。
- 下一项工作按异常、运行控制器、活动研究、待激活批准、历史研究排序。同优先级研究按最近时间排列；标题旁显示策略或组合名称及短 ID，完整 ID 仍可检查。
- 命名工作区只恢复展示与只读记录选择，剥离待应用的组合假设指令。来源、用户、刷新和浏览器返回的隔离规则继续适用。
- 手机入口和冲突选择保留完整文字及可点击尺寸；不另造一套简化后丢失证据的手机流程。

## 依据与边界

[NN/g 对 journeys 与 flows 的区分](https://www.nngroup.com/articles/user-journeys-vs-user-flows/)提醒我们分别检查跨阶段目标和具体任务步骤。[QuantConnect 的 project 模型](https://www.quantconnect.com/docs/v2/cloud-platform/projects)将研究、回测、优化和部署连接在同一项目中。由此得到的设计判断是：用户连续工作的中心应该是研究问题及其保存对象，导航菜单只是入口。这是设计推导，并非对这些产品的完整竞品测评。

浏览器回归证明确定性路径和安全约束，不能证明专业交易员的真实任务耗时、可发现性或团队协作满意度。没有声称本次进行过买方交易员实地用户研究，也没有把路径修复表述为行业顶尖认证。当前执行仍是本地模拟；实际交易权限不会因新的入口而改变。

## 中间失败与修复

初始 shell 路径验收为 34 通过、8 失败，暴露了组合配方草稿缺少 `lifecycle_events`。修复后定向的 120 项桌面／手机路径通过。强化资金成本和手机边界检查后，第一次全量本地验收为 329 通过、1 失败、8 个明确桌面专用手机用例跳过：风险轮动在目录晚到时没有自动补齐输入。同提交的 CI 为 330 通过、8 跳过，说明仅有绿色 CI 无法排除这个时序问题。我们没有将这次 CI 成功当作可发布依据。

随后增加明确控制数据到达时刻的回归，分别检查未编辑组合腿被准确补齐，以及已编辑组合腿不被迟到数据覆盖；原风险轮动验收也校验每条腿的准备包 ID。14 项对应桌面／手机路径通过。最后的冻结源码全量和部署证据随发布附件记录；本文件不会将中间版本的成功算作最终验收。
