# v0.6.0 自我 red-team：最终评估不能在恢复后重来

本次优先解决研究可信度：组合研究如果能在看过结果后修改参数、重新取数据或通过恢复旧备份重复最终测试，更多策略模板只会放大错误的信心。v0.6 增加了完整的冻结输入与一次性组合最终评估，以及财务恢复之外独立保留的研究事实。它没有把工作流约束包装成盈利或统计显著性。

## 已实现并验证的契约

| 攻击或故障 | 实际行为与证据 |
|---|---|
| 封存后数据目录、档位或结算 mark 改变 | 预览时捕获完整组合输入，封存绑定其哈希；计算和重放仅使用捕获包。现货和永续反例禁止所有后续 catalog 读取，仍能得到相同结果哈希 |
| 四个并发请求或重复点击最终评估 | 一个事务创建并消费 primary run；重复请求返回该 run，不再生成独立证据 |
| 队列已满与开始后计算失败 | 排队拒绝不消费；已经提交的评估失败仍消费，不能靠重试删除失败经历 |
| 换 dataset ID、周期、研究种类或不绑定项目 | 来源／市场／时间及指标预热暴露共享检查；这些别名不能绕过预留 |
| 恢复封存时的旧备份再测一次 | schema 6 恢复先核验并合并较新的预留、暴露、消费和试验事实；缺失 primary 明确为 consumed_unavailable，不能重新评估 |
| 伪造哈希正确但身份不同的事实 | 严格 body 字段与索引身份、稳定 ID 和哈希核验；同 ID 冲突在财务替换前失败 |
| 把重放计作第二次成功的样本外测试 | 固定原 run、输入、代码及结果身份，显示 replay/root lineage；不计作独立 primary |
| 拒绝或证据不足的结果被自动放行 | 预先声明现金基准、最低成交／观察数、收益、回撤及零债务条件；发布审查明确要求 rejected/inconclusive 确认，不改写结论 |

最低成交数指成交笔数，不是完整往返交易数。现金基准是此协议明确选用的比较，不代表所有策略的充分基准。观察或成交不足返回 inconclusive；它不意味着已通过其他条件。时间切分和旧版单策略研究保持各自原来的证据范围。

## 在真实生命周期试验中发现的问题

1. **并发开户仓位与报价枚举交错。** 一个组合取得报价时，另一个市场尚无仓位；准入时该市场已有仓位，经济账本正确拒绝不完整估值，但原组合把这个未成交的竞争当成永久失败。现在只对明确新增、缺失报价的市场重新取得报价，保留同一命令键；每轮有界重试，持续竞争保留待处理命令。真实账本测试插入一笔手动 SOL 成交，BTC/ETH 组合随后完成，手动所有权不受影响。
2. **SQLite WAL 消失引发运维接口 500。** checkpoint 能在 exists 和 stat 之间删除 WAL；改为一次 stat 并处理 FileNotFoundError。原失败记录保留，不标记为通过。
3. **旧订单回包清空新草稿。** 用户提交后修改下一笔订单，旧响应不应清空新输入。现在仅当当前草稿等于该请求 payload 时才清空；浏览器测试以受控延迟请求确认行为，不依赖任意等待时间。
4. **验收脚本误读正常 SIGTERM。** Uvicorn 可以在完整 lifespan shutdown 后返回 -15。脚本在原应用生命周期完整退出后记录完成标记，检查 offload 耗尽、supervisor 停止和进程租约释放；只看 exit code 不足以证明退出失败或成功。
5. **低于最小量的小幅调仓触发全组补偿。** 首次 v0.6 的 600 秒试验在最终核对发现 carry 组因正常小差额不满足最小量而失败。历史与前向现在共享最小调仓政策：同方向的小差额保持为可见残差，不改写目标；完整退出和方向转换仍减掉实际库存，不产生无法按当前最小量关闭的残仓。最初建仓过小、共同现金缩放后不满足最小量及超出已审查偏离限额继续失败。新增真实账本 60 次四小时步进、实际资金费及归因核对，并保留[原始失败记录](v0.6.0-soak-minimum-rebalance-failure.json)。
6. **Linux CI 暴露测试任务归属竞争。** API 验收同时运行真实队列 worker，测试助手的直接 compute 可能输给 worker，按设计不重复执行。助手现等待真实持有者的终态；没有禁用 worker 或放宽产品判定。

[原始失败记录与方法](soak-method.md)、[当前验证记录](../verification.md)分别保留故障、范围和最终结果。短时单机合成试验不能证明长期可用性或真实成交容量。

## 必须继续解决的产品差距

- **历史交易池与生命周期：** 当前市场集合不能证明包含当时已退市资产；合约改名、暂停、转换和结算也不能由当前规则反推。需要不可变、有来源且区分获知时间与生效时间的证据；当前 REST 快照不应冒充完整历史。
- **成交容量：** 当前研究模型是声明成本下的下一开盘全额成交。盘口深度、部分成交、队列、撤单延迟和价格冲击仍需独立模型及可复现数据。交易所执行还需另行授权；本地模拟账本不能冒充私有回报对账。
- **长期所有者归因容量：** 每次经济更新仍检查保留的所有者历史。应在保留损坏隔离和保护性退出契约的前提下实现聚合／索引与有归档证据的容量观测，不能简单跳过校验。
- **外部运维：** 单主机 SQLite 工作区尚不等于租户隔离、异地恢复或长期服务 SLO。目标部署环境及独立外部备份的验收需要真实资源与持续观测。

公开市场数据及平台外实验无法被本系统盲化；删除所有较新研究事实副本后也不能凭空恢复历史。封存可核验、失败可追踪、恢复不重新开放测试是已实现契约；统计有效性、市场覆盖与商业服务承诺需要各自的证据。
