# v0.10.0 交易员日常工作与产品审阅

审查日期：2026-10-09（Asia/Singapore）。只读审查基线：`8ef6b98d59ed6a356f8c975181bbf0b06488c34f`。范围：前端、API 源码、公开工作流／审计材料，以及仓库已有公开截图。未读取用户私有工作区数据、凭据，未运行服务或调用交易接口。后续授权实现发生在同一隔离工作树；本报告不把源码分析冒充真实浏览器验收。

## 判断

现有财务和证据契约已具实质内容，但交易员从开盘检查到异常处置的连续工作仍需自行拼接。研究与审批有稳定身份，事故列表保留库存责任；操作员仍缺少直接保护路径，且审批预算和组合库存曾存在具体的信息缺口。专业程度不能按页面、指标或测试总数判断。本轮没有把多租户、实盘或微秒执行当作当前本地研究产品的缺陷。

## 发现与整改

1. **异常到保护性减仓的入口断裂。** `DeskAttention` 原来仅跳组合详情，组合详情只有停止控制器，managed 视图隐藏通用订单票据。通用票据默认 BTC 现货买入且永续 reduce-only 未选；操作者须重新输入市场、方向、单位和数量。后台手工 reduce-only 不停止运行策略；单策略完全平仓后，下一根非零信号可再次开仓（`pro_execution.py` 的手工 ownership 分支及 `pro_service.py::execute_strategy_intent` 的零库存开仓分支）。本 agent 仅添加正确标记的保护 callbacks，统一保护对话框与 controller 停止由主实施者负责。
2. **有效账户预算未进入主审批视图。** 后台 `AccountCapital.preview.actual_admission` 已包含手工／pending 资本使用及逐 owner 的实际／承诺取最大值，前端原来只显示声明承诺。现已优先显示权益分母、来源、真实估值时间、已有有效占用、拟议后占用、剩余预算和超限金额；逐 owner 依据可直接审阅，声明承诺移至次要详情。文案明确预算余量不是可用现金。时间缺失时直接说明，不以浏览器时间或 policy 更新时间替代。
3. **组合库存原来按市场名取账户总仓。** 旧组平仓停止后，同市场新手工仓会被误显示为旧组的 Actual inventory。现已使用成功的 `/execution/contributions` 报告中 `owner=portfolio:<group id>` 的 markets 数量；账户净仓和全部当前 owners 分列。成功报告在服务端通过 sleeve 哈希、数量、方向、成本基础和账本校验；金额 `reconciled=false` 可能只是缺少价格／funding，不能隐藏已知数量。真正归属损坏或查询失败显示 Unknown。
4. **前向观察证据工作台仍不完整。** UI 原来没有窗口选择，验收结果藏在折叠 JSON，冻结结果只保存在组件状态；重新进入后无报告入口。此项由主实施者单独处理，本 agent 未修改 `ForwardPerformance`。
5. **审批按钮原来位于收益与经济证据上方。** 本次在审批表之前展示绑定 run／version、假设、财务评估窗口、净收益、最大回撤、实际敞口、费用、funding、最终权益、成交数及预登记淘汰结论。开发／按时间划分测试／一次性保留集分别标识，开发与测试指标分窗列示。没有淘汰评估时显示未提供；计算完成和模拟批准不宣称投资优势。全窗口边界使用结果哈希与版本一致的已绑定 run manifest，不能从新 run 或当前行情推断。

## ownership 与保护动作边界

现有减少净仓的成交按该市场当前 owner 数量比例分摊。此请求不专属于选中组合。因此新按钮标为“减少账户净仓”，明示影响所有 owners，传递实际账户 position 给统一保护对话框。选中组自身数量为零时不显示其保护按钮；归属未知或 manifest integrity 错误时保留“检查账户持仓”入口，不假装知道组合份额。该按钮本身不绕过后端限额、精度、只减仓和事务校验。

## 最小严格 UX 验收

- 10,000 USDT 权益、手工使用 30%、拟议组合 60%：主审批显示已有有效 30%、拟议后 90%、剩余 10%；30%＋80% 显示 110% 及超限 10%。同 owner 实际与承诺不能重复相加。缺少估值则有效余量 unavailable；所有百分比标清权益分母，金额带 USDT。
- A 已结束并平仓，B／manual 同市场新持仓：A 归属数量为零，账户列显示新总仓，A 没有保护按钮。A 残仓与手工仓混合：只显示 A 份额并列全部 owners，保护文案明确影响账户净仓。
- sleeve 损坏、quarantine、查询失败：组库存 Unknown，不能退回账户总仓或假定零；manifest 损坏仍可检查账户持仓。仅价格／funding 不完整且服务端数量校验成功时，保留真实 owner 数量，并说明金额状态不完整。
- 审批前可见精确研究版本、窗口范围及淘汰结论；全窗口与测试窗口不得共用一个无范围 Return。未通过／尚无结论的 holdout 在批准前仍清楚可见。
- 统一保护流程需先停对应 controller／整个 managed group，再重读库存、校验原生单位与预览。停止失败不能提交；重复提交幂等；空头以买入 reduce-only 平仓。完全平仓后下一根有效信号不得再次加仓，直到明确重新部署。此验证归主实施者的真实 UI／运行验收。
