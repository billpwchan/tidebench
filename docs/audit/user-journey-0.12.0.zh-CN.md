# v0.12：从用户任务审查平台

基线是 v0.11.0 `5b41f4aa3b35e339a153b760bf3e57c28265f71e`。三位路径 agent 分别检查研究、导航和执行，另一位独立上下文审查者交叉核对最终用户任务；主实施者负责相互挑战、整合和真实后端验收。这是项目内部审查，不是任何交易机构的可用性或生产背书。

## 审查方法

先定义用户要完成的工作，再检查每个交接是否保留目标、身份、输入、来源和操作后果。对每条正常路径加入离开页面、刷新、返回、请求失败、取消、晚到响应和部分状态不可读取的反例。测试不能只看成功提示；必须读回服务器保存的配置、研究责任及控制器状态。

外部依据采用 [QuantConnect 部署流程](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/deployment) 中明确的配置与激活步骤、[状态核对](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/reconciliation) 对研究与实际运行差异的处理，以及 [W3C 焦点顺序](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) 对可预测导航的要求。它们提供流程设计原则；不能据此推断 Tidebench 具备这些产品的完整能力。

## 复现的交互断点与实现

| 用户任务与反例 | 基线行为／实质问题 | 本轮实现 |
|---|---|---|
| 新工作区进入后决定下一步 | 导航菜单表达模块，但用户要自行决定先做什么 | 读取当前来源的七类任务快照；首个研究包给出具体入口；任务状态缺失就显示重试 |
| 刚减少持仓后从执行页返回首页 | 15 秒缓存可能把旧账户金额与新的零敞口拼在一起 | 金融指标与持仓使用分析报告捕获的同源账户；返回强制刷新；缺少匹配捕获时敞口保持未知 |
| 已有失败历史且有多项活动工作 | 失败列表与运行工作混合，旧错误可能淹没今天的任务 | 经济问题与活动工作优先；历史失败单列；主列表和历史均可展开；分页边界明确 |
| 先选策略，再去准备数据 | 数据回流可能清掉已选版本 | URL 保留版本／包／返回意图；返回绑定确切输入，保留编辑成本与方法 |
| 组合分两次准备市场数据 | 切页丢失假设、权重与另一条腿 | 用户／来源隔离的草稿及目标腿交接；两次回流分别填入正确腿 |
| 修订组合、刷新后用明确链接查看历史 | 恢复的 editing 标志会遮住 URL 指定结果，地址正确但可见任务错误 | 明确结果优先显示，Resume 回到原草稿；异步修订响应须仍匹配当前任务与编辑代次 |
| 编辑到一半刷新或看另一模块 | 本地 state 消失 | 策略编辑、单策略研究和组合研究使用经过形状验证的会话草稿；清除含义明确 |
| 修正非法规则 JSON 时离开 | 只保存解析后的 rules，损坏原文无法恢复 | 原始文字单独保存；无效解析仍阻止提交；UI 草稿字段不进入金融配置 |
| 新建单策略研究与查看结果采用同一个布局 | 空结果占据主区域，配置与 Run 被挤在窄侧栏 | 未选结果时配置在前、历史紧凑展示；选择运行后结果在前并聚焦标题，切换不重建草稿 |
| 打开历史结果继续审查 | 自动选择最新结果或复制配置，会把旧结果误认为当前草稿 | 结果选择与配置编辑分离；显式复用才覆盖配置 |
| 等待加载／创建／回放时开始新任务 | reset 或卸载不会阻止旧 mutation 成功回调，迟到响应可能覆盖 lineage 或恢复旧页／旧来源 | 请求绑定用户、来源、编辑代次和提交快照；服务器任务保留，当前草稿与导航只接收仍属于自己的回执；过期研究提供明确查看入口 |
| 激活期间换页、换来源或重新审阅 | 旧激活／预览／审批回执可能跳回旧控制器或污染新审阅 | 回执绑定挂载任务、实体和窗口代次；导航、关闭、重新审阅使旧 UI 应用失效；已保存事实继续可查 |
| 重复点击已经选中的研究标签 | 触发导航清掉 URL run，结果短暂可见后消失 | 当前标签保持当前任务；真正切换标签才更新导航 |
| 刷新已选研究、审批或控制器 | 仅保存页面名，具体任务身份丢失 | 结构化 URL 保存子页、来源、任务、包、版本与市场；前进／后退恢复原选择 |
| 旧链接指向缺失或错误来源对象 | 静默使用另一条记录或空表单 | 显式缺失／来源错误；未就绪数据包要求先检查准备状态 |
| 找五个默认币以外的市场 | 搜索目录是静态少量列表 | 查询当前来源 eligible USDT spot/SWAP catalog；Inspect 展开行情、Trade 锁票据；不产生订单 |
| 完成审批后查看刚激活的任务 | 跳通用执行页，需要再寻找 | 使用实际激活回执的 deployment/group ID；精确选择并可刷新 |
| 看已激活批准确认今天是否运行 | 历史 deployed 容易被理解为当前 running | 历史 Activation recorded 与实时 Current controller state 分列；读取失败显示 unknown |
| 从组合成员停止一条策略 | 普通 Stop 实际影响全组 | 改为 Stop whole portfolio；提交前明确全组、市场、来源和保留库存；取消不调用 API |
| 窗口／成本选错，研究已在跑 | 没有单任务取消入口 | durable requested → actual worker cleanup → confirmed；事务终态栅栏，不影响其他任务／执行 |
| 取消后服务重启，或恢复较旧备份 | 可能把缺乏退出证据当作已停止，或使旧任务复活 | 身份 token／内核锁及 inode 核验真实退出；缺证据持续 requested 并说明阻断；旧备份保留较晚的取消责任和尝试 |
| 取消 final evaluation 后重新运行 | 可能以交互取消理解为研究事实被撤销 | final consumption 与试验记录保留；取消不恢复未见样本资格 |
| 全局运营监控切到 Example | 来源栏容易暗示运营也只看 Example | 运营明确覆盖所有来源；流动性观察明确使用公开 OKX 数据 |
| 键盘切页、退出搜索、窄屏操作 | 焦点可能留在隐藏区域或覆盖层 | 页面切换聚焦主内容，Escape 返回搜索触发器；桌面与移动路径分别验收 |

## 状态设计的四个约束

1. **链接表达选择，不能表达执行授权。** 页面／来源／对象 ID 可复制与恢复；激活、停止、订单始终由现有角色、CSRF、服务端事务与当前账户检查决定。
2. **编辑意图与不可变事实分开。** 浏览器草稿恢复成本与工作文本；服务器保存版本、研究结果和审批。打开历史只改变当前查看对象，显式复用才修改草稿。真实数据 DTO 的 source 字段曾使中间实现错删有效草稿，因此本轮对服务器输入做窄归一化，并以真实响应形状验收。
3. **操作请求与观测终态分开。** 点击取消只代表已提出请求；计算／进程回收事实决定何时确认。停止全组与减少库存使用不同动作和回执。读取失败不能用旧事实补成当前成功。
4. **历史决策与当前经济责任分开。** 批准中的已激活是历史事实，运行状态要另外读取；停止控制器仍有库存与资金责任；取消试验仍有已暴露样本责任。

## 验收与证据范围

最终验证结果记录于 [verification](../verification.md)。[验收过程](acceptance-history-0.12.0.md) 保留失败阶段及修正，不把初次失败隐藏为最终成功。

- 真实后端路径从 UI 保存策略、编辑成本、准备数据、返回与刷新，到服务器配置绑定、研究完成、审阅批准、激活及精确控制器查看／停止。
- 实际 managed group 验证取消停止不改控制器，确认停止全组并保留原生库存；历史批准仍是 activation record，当前组为 stopped。
- 控制 fixture 专门覆盖 UI 难以稳定触发的目录失效、晚到取消响应、部分任务读取失败、非法 JSON、损坏存储和来源／用户隔离；这些是故障注入，不伪装为公开交易所观测。
- 取消 core 使用实际 SQLite、默认独立子进程与非隔离协作检查，验证不提前确认、临时目录清理、完成竞争、final consumption、权限／CSRF 与重启责任。实际 SIGKILL、暂停旧 watcher、launch 记录间隙和不同时间点旧备份均有反例；未知 PID 不被发送信号。

## 产品判断

本轮缩短的是具体操作断点，尤其是跨页继续同一工作、控制器身份和停止／取消的经济含义。功能数量、截图美观与测试通过不能单独证明顶尖机构的生产水准。

工作区仍以单数据库单写者、自托管、真实公开行情及本地模拟为边界。会话草稿是当前浏览器工作恢复，并非跨设备协同编辑。已有策略的负面研究结论与行情证据保持原身份，本轮没有新增可持续 alpha 宣称，也没有将短时测试替代真实长期运行记录。完整策略研究、撮合逼真程度和用户长期行为仍各自需要相应证据。
