# v0.7 自我审计：不能把当前品种表当成历史

v0.6 解决冻结组合评估和恢复后重复测试；本轮继续处理研究输入的根本缺陷。根据 [OKX 官方更新记录](https://www.okx.com/docs-v5/log_en/)，新上市条目可以先出现、交易规则稍后补全，instruments WebSocket 也可能只推送变化的品种。本轮仅捕获 REST 完整响应的 data 数组，不把增量消息、缺席或旧上市时间当成完整历史。

| 反例 | 已实现的结果 |
|---|---|
| 健康 BTC 与空规则新币同一响应 | BTC 仍可用，新币与原始缺失字段完整保留，不借用其他品种的最小量 |
| 无效数值、单位或重复品种 | 单条隔离、明确未知／不受支持；不随机选一条，其他健康成员不丢失 |
| 规则 A → 暂停 B → 规则 A | 三次独立不可变观察保留；重复经济规则不覆盖时间线 |
| 新响应漏掉以前的品种 | 当前查询拒绝旧缓存；diff 只记未观察到，不推定退市或清零 |
| 查询时间早于第一次观察 | 返回覆盖未知；今天拿到的旧 listTime 不能证明过去已获知 |
| 在两次观察之间或超过时效 | 明确沿用假设／全部未知；不宣称连续可交易性 |
| 缓存有效但已过公布的到期时间 | 当前规则查询拒绝继续使用，不生成未经证据支持的结算价 |
| 浏览器接收 19 位纳秒整数 | 改用精确字符串，原始观察导出可按服务器契约核对 SHA-256 |
| 恢复捕获新证据之前的备份 | 财务恢复前合并新观察；当前查询不回退到旧元数据缓存 |
| 观察／行情规则代码改变但沿用旧发布审核 | 这些模块纳入研究和运行代码指纹；真实账本反例在新 K 线核对拒绝旧组继续发命令，既有订单与库存保持不变 |
| 哈希正确但相同 ID 的内容冲突 | 在替换财务工作区之前拒绝，保留当前身份与证据 |

实际验收发现并修复了 SQLite 普通连接返回 tuple、工作区连接返回 Row 的兼容问题，以及浏览器时间输入的规范化问题。原始观察限制为最多 10,000 条／8 MiB，查询页最多 100 次观察，避免无界响应。观察留存总量尚无长期容量承诺。

[真实公开验收记录](v0.7.0-public-instrument-observations.json)包含 1,144 条现货、500 条永续响应条目、支持范围计数、原始数据哈希和持久化核对。该记录没有发布交易所原始数据，也没有使用私有凭据或交易接口。[工作流与精确导出契约](../instrument-evidence.md)说明接收时间、接口声明时间与覆盖范围。

仍未解决的是有来源的历史元数据导入、全部历史成员、动态交易池及持仓期间的退市／合约转换结算。默认时间查询只返回选定响应的成员；它不是所有曾上市资产的并集。没有事件和价格证据时，不能安全制造结算或转换。盘口容量、长期归因容量及外部运维也保持各自的实质缺口；本轮并未用新增界面掩盖它们。
