# v0.5.0 自我 red-team：从组合研究到可恢复的前向控制

本次审查针对三个具体问题：历史组合能否完整交给前向模拟、首腿成交后故障能否留下可处置状态、收益贡献是否能与真实经济账本核对。结论是这些契约已有实现与可复现证据；不能据此宣称整个产品已达到行业顶尖或完成正式商业验收。

执行范围保持公开行情、历史研究和本地模拟。没有交易所下单，审计不访问用户密钥。测试使用临时工作区，不能替代真实账户或生产环境的运维证据。

## 审查结果

| 实质缺口 | 本次实现 | 仍需区分的边界 |
|---|---|---|
| 历史组合无法交接前向 | 不可变组合版本→绑定研究→全组审批→事务激活→目标／命令／成交记录 | 历史下一开盘成交与前向观察 bid/ask 不保证相同经济结果 |
| 每腿各自抢现金 | 共同账户估值与声明资本占比；先减仓，再用实际释放现金共同缩放增加量 | 资本占比不隔离资金，也不保证所有组合同时获得目标现金 |
| 首腿后中断或拒单 | 冻结目标／增加计划、稳定命令键、先续作旧批次、持久补偿与可见残差 | 多腿顺序执行存在裸露时间；补偿也可能失败 |
| 名义策略收益冒充归因 | 基于实际成交／资金费的虚拟持仓、独立成本、比例减仓与账户核对 | 这是货币贡献，不是独立子账户净值、收益率或因果归因 |
| 升级与恢复漏掉新证据 | schema 5 的组／批次／命令／贡献完整性要求与安全恢复 | 跨 schema 必须使用匹配版本和升级前备份 |

## 发现并修复的反例

### 1. 归因损坏可能阻止保护性减仓

最初，贡献记录的完整性检查是所有经济变更的共同前置条件。它能阻止在坏账上新增风险，却也可能阻止止损、强平或实际资金费结算。这使辅助记录故障变成无法减仓的风险。

修复后，新增风险仍被阻止；合法减仓及实际结算允许完成经济事务，归因进入持久隔离状态。局部贡献写入使用保存点，失败只回滚辅助归因变更。原始坏记录保留，隔离事件捕获实际经济前后证据，账户暂停新增风险，报表明确不可用。不自动猜测所有者或重写旧记录。

损坏矩阵涵盖无效 JSON、缺字段、NaN、Infinity 和巨大指数，并分别验证保护性减仓、资金费和穿仓强平。归因专属解析受界限约束，隔离不应改变实际损益，也不能被清除普通风险暂停绕过。实际经济账本的失败仍必须暴露，不能被误分类为可忽略的辅助故障。

### 2. Decimal 绝对值舍入留下虚拟残仓

交错的多来源入场、比例减仓、再次入场和最终全平暴露了有限精度问题：比例分摊的最后一个所有者接收精确有限小数余数，该值可能多于核心运算上下文的 50 位。对它调用受上下文影响的绝对值运算，可能再次舍入，导致实际净仓已为零而虚拟数量仍有微小余额。

修复使用不舍入的绝对值复制，完整关闭保留精确所有者数量，并增加虚拟数量与净仓同向、成本非负的约束。测试用多轮交错操作覆盖现货、永续多头及永续空头，最终关闭必须没有虚拟数量或成本。合法有限精度差额仍有明确界限和事件证据；损坏记录不能以“误差”名义自动重置。

### 3. 已成交但未确认的命令可能重做

进程可在经济订单提交之后、批次命令更新之前退出。恢复若仅看命令状态，会再次发单；若重算数量，又会改变原始决策。

恢复先用原始幂等键和 payload 核对实际订单，已提交成交被关联回命令。未完成批次优先于新决策；冻结的目标和增加量保持哈希不变。未成交命令重新取得当前报价，不能用停机前价格补成交。

### 4. 保护订单与补偿命令交错

补偿计划冻结后，保护订单可能先减少某腿库存。直接提交旧补偿量可能超出剩余仓位；修改原 payload 又会破坏重放证据。

旧命令保留并标记 superseded，新命令以新键记录剩余 reduce-only 数量。库存反复变化时，有界重试失败会保留受阻状态，而不会自动宣称补偿完成。

### 5. 发布审查忽略实际执行政策

研究成本及风险上限与账户当前政策可能不同。组合审批现明确显示费用、滑点、清算费用、总敞口和日损限额差异；差异必须确认。激活在事务内重验 preview 哈希、空仓、挂单、所有权、杠杆与部署数量。执行时再检查当前政策；旧审批不能授权无限期的政策漂移。

### 6. 移动布局和异步截图掩盖实际状态

初次组合页面仍继承手动订单侧栏，移动端需滚过大量无关表单才能看到所需证据。组合／贡献页已使用完整内容宽度。浏览器验收在捕获截图前等待实际目标批次和非零持仓；页面刚加载的空状态不能被当作成功演示。截图使用明确合成数据，不表示策略盈利表现。

### 7. 历史展示上限不能决定活跃任务和异常集合

组合历史展示有界是合理的资源控制，但用“最新 200 条”结果做调度会让更早的活跃／受阻组从运行和告警中消失。调度现在查询完整的 active 集合，异常审查使用完整 attention 集合；界面列出全部活跃组及最近 200 个非活跃组。历史数量不应决定是否继续处置经济风险。

### 8. 策略起点要写出失败条件

新增四个可编辑组合研究起点：保留现金的 BTC/ETH 篮子、共同现金下的趋势／回归、七日正动量及滞后资金费研究。它们默认时间切分，假设中写出同日期基准、成本压力和拒绝条件。参考参数不是经过验证的 alpha，文本要求的额外比较也不等于程序已自动运行这些比较。

### 9. 单组 manifest 损坏不应退出全部调度

实际注入一坏一好组合后，旧实现的集合解码会退出整个策略 supervisor；健康组没有批次，坏组也无法在界面加载或停止。修复让调度读取可信索引，每组独立验证。展示端返回 `manifest: null` 与明确的 `integrity_error`，不显示未经验证的内容；停止依据数据库所有权撤销执行，保留原坏记录和已成交库存。

哈希损坏、无效 JSON、重算哈希后的身份漂移三类实际测试均确认：健康组完成交易；坏组直接经济命令被拒绝；独立停止不影响健康组，停止后完整性事件仍可追踪。成交事务同时检查组的哈希、索引身份与腿成员关系。

### 10. 缺失估值不能被后续陈旧价格掩盖

多市场账户曾在先遇到缺失价格、再遇到陈旧价格时，把 `unavailable` 覆盖为 `stale`，显示漏算资产的部分净值。现在严重性单调聚合：任一必要价格或永续档位缺失，完整净值、总未实现损益和维持保证金保持不可用。测试交换市场顺序并覆盖缺价格与缺档位，防止依赖遍历顺序。

### 11. 单腿亏损预算不能破坏 carry 目标比例

独立限制某条腿的 notional 会使等名义资金费组合变成不对称方向敞口。历史与前向现在共用权重限额函数：carry 按两腿最严格的亏损预算共同缩放；一腿退出则两腿退出。实际研究与前向测试使用仅现货腿有亏损预算的配置，验证两腿目标权重等幅反向、实际数量按各自合约单位取整。顺序成交与取整仍可留下明确残差。

### 12. 换周期与极端数字是研究边界

保留集访问保护改为来源、市场、时间重叠，跨 K 线周期一致。既往暴露检查使用既往数据自己的周期计算指标预热范围，避免换周期绕过或把短周期预热错误放大。实际测试涵盖单策略、组合、预热区间和重复封存；原始公开数据仍不属于盲化保障。

极短科学计数输入可能展开成巨大的固定小数字符串。输入模型现在在持久化和规范化前约束 Decimal 的有效精度和指数；正常精确值不经全局上下文舍入。HTTP 反例必须返回 422 且不创建研究或组合版本。输入模型和 API 定义也加入实现身份，避免其变化被旧研究身份遗漏。

## 实际故障注入观测

数据来自 [v0.5.0-managed-observations.json](v0.5.0-managed-observations.json)，可运行 `uv run python scripts/managed_portfolio_audit.py` 重现。审计调用真实应用、SQLite、经济账本与备份恢复服务，行情为禁止网络访问的合成提供方。

| 场景 | 实际观测 |
|---|---|
| 子进程在首笔成交后硬退出 | 退出码 23；恢复前 1 笔已提交；恢复后 4 条命令对应 4 笔唯一成交；目标与增加计划哈希均未改变 |
| 共同现金缩放与残差 | 实际现金缩放约 0.99840065；残差约占声明资本 0.15993997%；批次 completed |
| 贡献与账户核对 | 该故障场景净贡献与账户净 P&L 同为 −15.9939223215014583 USDT；不是盈利示例 |
| schema 5 真实恢复 | 数据库实际替换后组 stopped、风险 halted、合成时钟 paused；命令证据及贡献所有者保留并可核对 |
| 第二腿拒单且补偿也失败 | 状态保留 compensating，仍有 1 个持仓并显示原因；故障解除后 batch compensated、组 failed、剩余持仓 0 |

这些数值只属于捕获的输入和环境。独立脚本退出成功不等于完整产品验收，亦不能推导最大容量、真实盘口表现或长期可用性。自动化测试最终计数和运行环境由[验证记录](../verification.md)单独记录。

## 仍然实质缺少的能力

### 组合研究治理

组合不可变版本、父修订、研究绑定和审批身份已经实现。现有单策略的一次性保留集、跨 run 候选计数与访问保护不能被描述成组合也已获得同等治理。组合需要独立的冻结最终测试定义、一次性消费、试验／候选登记和跨版本泄漏边界。当前组合时间切分测试固定构建规则、重新起始测试账户，但仍会被重复观察和反复修改假设。下一轮还需在备份恢复时保留已消费／已暴露区间的 tombstone；正常运行内的一次消费不能被夸大成抵抗整个工作区历史回滚的保证。

[回测过拟合论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)说明投资策略的选择过程不能仅靠一次样本外指标证明有效。本实现没有 PBO／CSCV，也不能追踪平台之外的实验；不能把 workflow holdout 写成统计有效性的保证。

### 历史交易池与合约生命周期

当前显式市场集合与捕获规则可以复现“这些市场、这些规则”的情景，不能证明无幸存者偏差。仍需有来源的历史上市／退市、可交易时间、暂停、合约转换及历史规则事件，按决策时点决定交易池与结算行为。当前维持保证金档位继续是情景输入，除非提供有来源的历史证据。

### 容量和成交微观结构

共同现金缩放、子命令拆分及残差限制是账户与流程控制。全额成交模型仍不包含盘口深度、排队、部分成交、冲击、容量、撤单延迟或成交回报未知状态。它不能证明真实资金可按回测规模执行。交易所执行需要独立授权和私有回报／未知状态对账适配器。

### 持久所有者历史的容量

贡献核对当前仍在每次经济更新扫描保留的 owner／sleeve 历史。即使活跃仓位有界，已关闭来源长期积累也可能增加保护性平仓延迟。需要不削弱完整性检查的聚合／索引优化、生命周期基准与目标硬件观测；本次不把未归档的单次本机观察写成容量或 SLO。

### 真实经过时间的运维证据

进程硬退出、请求负载、备份替换和模拟时间推进分别证明有限契约。仍缺目标部署环境下的长时间连续运行、行情故障恢复、资源趋势、备份外部复制／恢复和明确 SLO 观测。加速合成时钟不能替代真实经过时间，也不能把短时 p95 当长期 SLA。

### 部署边界

当前是单进程、单 SQLite 写入者的共享工作区。角色权限不等于租户隔离；局部备份不等于异地主机灾备。实际 HTTPS、保护的异地备份、主机维护与可响应的运营人员仍是托管环境的交付内容。

继续迭代的依据应是上述具体经济和运维契约及反例，而不是功能数量、截图完整度或“production-ready”标签。
