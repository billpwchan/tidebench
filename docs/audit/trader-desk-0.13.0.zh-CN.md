# v0.13：以账户判断和研究决策重整工作台

这次评估以实际使用路径为单位：打开工作区后判断账户情况；找到持仓并处理保护动作；监控大量委托；按预算准备模拟单；保存假设、准备对应数据、运行研究、识别结果配置并比较试验。界面密度服务于这些动作，不能把说明和任务模块放在决策之前。

## 调研及独立评估

查阅时间：2026-10-11。以下是官方使用资料，设计取舍是本项目的推断，不表示平台已经达到这些产品的功能或机构验收水平。

- [IBKR Mosaic Layout](https://www.ibkrguides.com/traderworkstation/mosaic-layout.htm)：账户概览、持仓、委托输入和委托监控有独立职责；窗口可关联同一市场。用于检验首屏的账户与操作组织。
- [IBKR Monitor Panel](https://www.ibkrguides.com/traderworkstation/monitor-panel.htm)：账户、持仓、保证金和市场监控相互连接。用于检验进入账户后是否能直接找到风险和持仓。
- [QuantConnect Live Results](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/results)：区分运行指标、持仓、委托事件和日志；用于检验研究结果与当前账户事实是否混用。
- [TradingView Positions and Orders](https://www.tradingview.com/support/solutions/43000763362-positions-and-orders/)：展示与当前市场关联的持仓和委托；用于检验市场选择后是否保留具体操作对象。

评估从交易员判断、产品布局、研究工作流三个角度展开，另由不参与本轮实现的代理复核请求与数量边界。审阅依据源码、截图与可复现反例，不虚构 Jane Street 员工意见，也不把代理评审称为机构认证。

## 确认的实质缺口与处理

| 使用情境 | v0.12的问题 | v0.13的设计 |
| --- | --- | --- |
| 开盘检查账户 | 六项研究待办可将账户、风险和第一条仓位推到首屏之外 | 账户与风险先显示，工作簿为主区域，继续研究压缩为次区域 |
| 从持仓入口进入执行 | 小屏先出现新增风险票据，委托在九个平级标签的后部 | 默认进入工作簿，持仓与委托常驻；新增模拟单由明确动作打开，可关闭并保留草稿 |
| 查看资金账本或发布记录 | 无关的新订单表单固定占据右栏，账户会计和风险重复铺开 | 分组选择分析与控制视图；票据只在发起订单时出现；明细渐进展开 |
| 核对十二个市场及三百个委托 | 横向滚动会丢失市场身份和动作，不能按损益排序或筛选 | 桌面固定身份与动作，按数值排序和筛选；窄屏每市场摘要保留关键量与动作，其他字段可展开 |
| 低价币报价 | 固定五位小数把有效正价显示成零，也抹平价差 | 价格按tick显示；缺规则时保留有界有效数字；USDT金额维持独立精度 |
| 用名义预算准备单 | 必须手算基础数量与不同永续的合约张数 | 用精确十进制整数换算，按lot向下取整，显示余量；显式应用后再走服务端预览 |
| 从永续假设准备数据 | 数据表单回到默认现货和1H，直到运行时才报错 | 产品、市场、周期和UTC窗口随研究路径传递，刷新后仍可核对 |
| 配置一次研究 | 长表单、通栏哈希和空历史占据空间，运行按钮远离决策 | 输入、机制、成本与验证分组，运行栏可达，宽屏三列并列配置，历史提供人可读的市场和假设 |
| 审阅已完成研究 | 当前可编辑草稿与历史结果配置混在同一个视觉上下文 | 已评估配置与证据范围为独立只读摘要，编辑下一试验保持明确边界 |
| 对比或修改假设 | 版本与试验主要通过哈希辨认，差异留在JSON | 假设和参数摘要、关键配置差异可读；原始清单与JSON仍可检查 |

## 交互反例

独立审阅和完整浏览器路径还复现了四个不能靠视觉截图发现的问题：合成时钟快进后的预算误拒绝、收起的无效辅助预算阻塞合法原生订单、极小tick被统一输入步长拒绝，以及手机审批表格遮挡按钮。修复后的验收保留真实预览请求、普通按钮点击和原记录身份检查。三百条委托通过筛选和分页访问；窄屏记录区域限制高度，页码变化重置内部滚动，避免把整个交易台变成长列表。

## 判断边界

预算换算目前适用于市价单；限价与止损单使用明确原生数量。预算计算只估算名义数量，未包含费用、滑点或保证金阶梯。它不会自动发单，OKX 行情过期、异常未来时间或规则不完整时不能应用数量；Example 报价遵循其可快进的合成时钟；服务端预览与执行仍检查资金、风险和规则。截图中的合成价格、持仓与委托只用于检验密度和交互，不是实盘业绩。

这轮改变使用组织与呈现，不新增策略盈利证据、交易所订单路由或机构服务等级承诺。真实行情、回测与本地模拟执行的范围继续保持。

验收结果在 [verification.md](../verification.md) 中记录；中间失败与修复保留于 [本轮验收记录](acceptance-history-0.13.0.md)。
