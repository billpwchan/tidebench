# v0.4.0 自审：已闭环的能力与剩余实质差距

日期：2026-10-08。评审目标是交易员可以完成和检查的经济工作流，不以页面数量、测试数量或策略名称数量替代成熟度。

## 从旧缺陷到可复现行为

- RT-04：实际前向调度的首次准备读取 2,000 根；随后四次小时推进各读取一根。增量记录按市场／周期／时间唯一，旧检查点带内容和实现身份。机器可读证据记录数据库实际字节，不外推最大容量。
- RT-06：Example 时钟可暂停、加速和向前步进，时间与运行健康的墙钟分离。持仓、资金费、指标和退出随新确认行情推进；恢复暂停时钟。
- RT-07：一次执行周期对持仓／策略／待执行订单市场集合各调度一次行情；先返回市场立即处理保护性订单。对 ETH 行情注入等待时，BTC 止损仍成交。有限并发和请求超时仍会影响大量同时失联市场的延迟，未宣称 HFT 隔离。
- RT-08：候选共享完整输入，结果按内容压缩保存并核验哈希；界面只请求所选候选明细。队列、工作量、输入／输出字节和计算截止均有边界。Linux 额外虚拟地址预算不能当成总 RSS 上限；实际部署仍使用 OS／容器内存边界。
- RT-09：加入收盘通道、Z 分数、有界规则程序、退出与定仓；整段／分块／重启使用共同指标状态。多资产历史研究使用真实共用现金和账本，保留腿失败和残差。未用单腿收益相加冒充组合。

旧版 RT-01/02/03/05/10 的历史等待、库存／待执行订单接管、OOS 界面和用户名权限回归仍保留。原始审计与基线文件不被重写。

## 本轮继续挑战并修复

1. **平仓后的再次部署。** 数量为零的持仓行仍存在；错误地以行存在判断占仓，阻止了第二次部署。注册、部署和前向退出均明确判断非零经济数量，并验证两次设备工作流。
2. **研究草稿污染。** 新研究自动继承最近一次版本绑定参数，让用户误以为在研究自己的新假设。增加明确的新建研究操作，保留从策略／数据交接时的显式绑定。
3. **新数据不可见。** React Query 的空列表缓存导致刚准备的数据包／保留集数据暂时无法选择。进入对应工作区立即刷新，并周期更新状态。
4. **停止线程不等于停止计算。** 维护取消不能安全终止运行中的 Python 线程。默认改为受拥有关系约束的计算进程；超时、取消、异常和服务器突然退出均有清理验收。
5. **证据展示。** 正常读取也核对结果／观测哈希；决策显示退出原因、实际意图与订单。摘要按可读精度展示，完整 Decimal 留在明细和导出，避免长数字造成错误阅读。
6. **恢复完整性。** 真实研究、审批、部署、前向决策、压缩结果、净值、时钟和事件记录进入 schema-4 实际备份／恢复验收，恢复后停止策略并撤销会话。

## 仍不能称为完整顶尖平台的原因

| 实质差距 | 为什么不能用现有能力代替 | 下一验收契约 |
|---|---|---|
| 托管多资产前向策略与双腿故障处置 | 历史组合和多个独立单市场部署不等价 | 统一目标快照、持久执行批次、重启续作、停机竞态、残差限制及风险减仓 |
| 策略级贡献归因 | 账户 TWR 不能分配手动、多个策略与资金费贡献 | 订单／持仓代际归属、已实现和未实现 P&L、费用／资金费、现金流与账户完全核对 |
| 历史市场集合／退市和合约变更 | 当前市场集合和用户提供规则不能证明完整历史 | 有来源的上市／退市事件、已知时间、库存终止或换算模型以及缺失来源拒绝 |
| 组合研究的版本治理与冻结候选 | 固定政策的时间切分不是独立试验治理 | 组合定义版本、跨 run 试验登记、保留集一次使用和审查后整体模拟发布 |
| 有代表性的持续运行与故障恢复 | 秒级压测或加速时钟不能证明长期可靠性 | 真实经过时间、真实任务组合、故障／重启、资源趋势和明确 SLO 的可核验记录 |

公开源代码、单机部署和可复现测试允许验证当前边界。外部托管资源、数据授权、认证或长期服务时间不会由一份勾选表生成；本报告不据此虚构验收结果。

## 设计依据

采用 [LEAN 的职责边界](https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview) 与 [NautilusTrader 的事件／时钟设计](https://nautilustrader.io/docs/latest/concepts/architecture/)，保留现有账本的确定性并明确模型边界。参考 [Freqtrade 策略契约](https://www.freqtrade.io/en/stable/strategy-customization/) 将退出和持仓管理纳入定义。

研究治理参考 [Bailey 等人的过拟合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)，记录试验和访问关系，未冒称已实现 PBO 或 deflated Sharpe。运行治理参考 [Google SRE 监控原则](https://sre.google/sre-book/monitoring-distributed-systems/)，区分进程存活与工作进度。[Python 线程取消语义](https://docs.python.org/3/library/concurrent.futures.html) 和 [Linux parent-death 语义](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html) 直接约束计算隔离的实现。
