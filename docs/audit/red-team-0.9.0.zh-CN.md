# v0.9.0：组合风险配置自我挑战

本轮发现的实质差距是：原有轮动能够选币，但固定权重无法区分不同波动、相关性和现金风险；回撤下降也容易被误解为策略更强。实现了共享因果模型、可部署组合定义、冻结检验、实际账户风险统计及可检查的风险决策面板。

| 挑战 | 已完成的处理与证据 | 仍不能据此声称 |
|---|---|---|
| 用未来数据估计仓位 | 仅使用决策收盘时已知的连续确认收益；未来扰动、坏数据拒绝与逐次样本时点验证 | 历史数据即统计盲测 |
| 协方差样本误差与低波动放大 | 固定对角收缩、波动率下限、零方差排除、逐币上限、不向上加杠杆 | 实现了拟合 Ledoit–Wolf 或等风险最优解 |
| 加密资产共同暴跌 | 相关性压力矩阵与样本模型取更高风险，再统一降低仓位 | 对跳空、尾部或未来损失有硬保证 |
| 止损移除负相关腿反而增险 | 退出及亏损预算后重新通过同一个风险调节器 | 保护性减仓总能在所有未来状态下降低风险 |
| 固定目标与实际风险混淆 | 界面明确区分分配资金模型风险和账户实现风险；保留调仓之间的参考性质 | 20% 分配资金目标等于实际账户波动上限 |
| 更低仓位伪装为超额收益 | 固定时钟与资金上限，公开平均敞口、实际换手、静态与非风险动量对照 | 已实现严格风险匹配或投资优势 |
| 成本吞噬收益 | 28 个预定情景全部披露；双倍成本 B 主规格仅 +0.169%，42 样本邻域为 −1.381% | 应部署样本冠军或小幅正收益已具统计意义 |
| 小额调仓被默默当作成交 | 最小手数延期仍记录；全部案例共 128 次 `rebalance_minimum`，其余执行错误代码总数为零 | 128 次已成交或资金真实可在交易所执行 |
| 研究耗尽 CPU | 五百万协方差乘积准入上限，加既有进程、时限、内存及产物限制；准入拒绝测试 | 多租户或长期容量 SLO |
| 重启／回放改变仓位 | 实际账本集成、已验证历史、持久目标／命令及幂等恢复；冻结输入计算禁止读取可变目录 | 达到交易所撮合一致性或分布式容灾 |

[方法、来源及全部结果](../portfolio-risk-research.md)不隐去负面证据：风险减仓降低了回撤，仍不能建立净收益优势。两次相邻半年检验、三个当前选定市场和参数邻域具有依赖关系，未做统计显著性或家族错误率宣称。原始数据保留在隔离捕获库，公开产物只有市场元数据、方法、哈希、指标和代码级延期计数。

首次实验写出在一个结果后遇到 Decimal 序列化错误，已修复；没有据此调整策略参数。最终报告增加延期分类，在相同冻结捕获上重新计算，再进行完整回放。现有短期运行和旧版本耗时审计不冒充本版本长周期运营验收。

仍然存在的实质差距包括：订单簿容量与部分成交、完整历史成员与生命周期、独立长周期 forward 策略证据、长期运维容量、可靠收益来源。当前轮完成的是一个可审查的组合风险与策略研究闭环，尚不能称为已验证的顶尖商用交易系统。

最终又用真实 OKX 公开历史及当前报价跑通隔离工作流。当时策略选择现金，零策略订单；另行标注的约 100 USDT 手动本地模拟探针验证了买卖报价、手数、手续费及平仓。控制器重载未重复目标或订单。此单次集成观察不代替长期 forward 或成交容量验收。双语收尾测试初次因测试脚本仅识别英文导航而超时，修正本地化选择器后桌面／移动全部通过；交易数值代码未改变。
